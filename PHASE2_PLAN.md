# Phase 2 Implementation Plan: Hybrid Search RAG with Qdrant Native Hybrid

**Goal:** Implement a Hybrid Search RAG system combining dense and sparse vector search using Qdrant's native hybrid search capabilities (Dense + Sparse), integrated into the `rag-evaluator` framework.

## 1. Environment Setup & Dependencies

### 1.1 Qdrant Deployment

- **Task:** Set up Qdrant instance via Docker (as per user selection).
- **Details:**
  - Create `docker-compose.yml` with `qdrant/qdrant:latest`.
  - Map ports `6333` (HTTP API) and `6334` (GRPC).
  - Configure volume for data persistence.

### 1.2 Python Dependencies

- **Task:** Update `pyproject.toml`.
- **Dependencies:**
  - `qdrant-client`: Official Python client.
  - `fastembed`: For generating sparse vectors (e.g., SPLADE) on the client side.
- **Action:** Run `uv add qdrant-client fastembed`.

## 2. Hybrid RAG Implementation

### 2.1 Configuration

- **Task:** Define chunking and search parameters.
- **Specs:**
  - **Chunk Size:** 700 chars.
  - **Chunk Overlap:** 100 chars.
  - **Sparse Model:** `prithvida/Splade_pp_en_v1` (via FastEmbed default or configured).
  - **Fusion Alpha:** 0.5 (default weighting for hybrid query).

### 2.2 HybridRAG Class

- **Task:** Create `src/rag_evaluator/rag_implementations/hybrid_search/implementation.py`.
- **Details:**
  - Inherit from `BaseRAG`.
  - **Initialization:**
    - connect to Qdrant.
    - ensure collection exists with named vectors:
      - `dense`: `text-embedding-3-small` (1536 dim).
      - `sparse`: `sparse` (generated by SPLADE).
  - **Indexing:**
    - Generate dense embedding via OpenAI (`self.embeddings` from BaseRAG).
    - Generate sparse vector via `fastembed.SparseTextEmbedding`.
    - Upsert points containing payload (text, metadata) and named vectors (`dense` and `sparse`).
  - **Retrieval:**
    - Use `client.query_points()` (prefetch feature for hybrid).
    - Prefetch 1: Dense search.
    - Prefetch 2: Sparse search.
    - Query: Rerank/Fusion (Qdrant `fusion` query or explicit weighting).
    - *Note:* Qdrant's Python client simplifies this with `QueryRequest` or simple `search` if using single vector, but for hybrid we use the hybrid query API.

## 3. Evaluation & Testing

### 3.1 Tests

- **Task:** Write tests in `tests/unit/test_hybrid_rag.py` and `tests/integration/test_hybrid_rag_flow.py`.
- **Scope:**
  - **Connection:** Verify Docker container is reachable.
  - **Embeddings:** Verify sparse vectors are generated (non-empty).
  - **Retrieval:** Verify a keyword-specific query returns the expected document even if semantically distant, validating the "hybrid" aspect.

### 3.2 Evaluation Run

- **Task:** Run the evaluation pipeline.
- **Command:** `rag-eval evaluate --method hybrid_search`.
- **Success Criteria:**
  - Successful run without errors.
  - Improved scores on "keyword-centric" test cases compared to Pure Vector baseline (from Phase 1 report).
